\section[Multi-Agent Pipeline for Downstream Task Evaluation]{Multi-Agent Pipeline for Downstream Task\\Evaluation}
\label{sec:multi-agent-overview}

The proposed multi-agent pipeline is a confidence-aware downstream evaluation framework designed to support robust and interpretable prediction on Arabic-English code-switched text. The pipeline begins with a task-specific primary classifier that produces an initial prediction and confidence score for each input sentence. When this prediction is sufficiently confident, the system accepts it directly. However, when the classifier is uncertain, the sentence is not immediately assigned a final label. Instead, it is escalated to a group of specialist reasoning agents that examine the sentence from different perspectives before a final decision is made.

This design reflects the intuition that uncertain code-switched examples often require more than one type of reasoning. A sentence may contain lexical cues that suggest one label, contextual meaning that suggests another, or task-specific ambiguity that cannot be resolved reliably by the primary classifier alone. For this reason, the proposed pipeline introduces specialist agents that provide complementary analyses of the same input. Each agent is guided by a role-specific instruction prompt and focuses on a particular aspect of the sentence, such as lexical evidence, logical consistency, sentiment polarity, contextual interpretation, or explanation generation. These agents do not replace the primary classifier; rather, they are activated only when additional reasoning is needed.

Within the scope of this thesis, the pipeline serves as the downstream evaluation component for assessing the quality of the Arabic-English code-switched data generated by the Task-Aware SwitchLingua framework. By applying downstream classifiers and specialist agents to the generated data, the pipeline provides an extrinsic evaluation of whether the generated sentences preserve the semantic and linguistic information required for real NLP tasks. At the same time, the pipeline is not limited to generated data; it is designed as a general-purpose multi-agent evaluation architecture that can also be applied to real code-switched datasets.

Figure~\ref{fig:overall-pipeline} illustrates the overall execution flow of the proposed pipeline. An input sentence first passes through the primary classification layer. If the classifier assigns a high-confidence prediction, the prediction is returned directly. If the confidence score falls below the routing threshold, the sentence follows the escalation path, where task-specific specialist agents provide additional reasoning. The consensus mechanism then combines the primary prediction and the specialist outputs to produce a final label. The explainability agent subsequently summarizes the reasoning behind the final decision in natural language.

To illustrate the general flow, consider an Arabic-English code-switched sentence such as: ``\textarabic{الدكتور قال إن ال} \textit{patient} \textarabic{محتاج} \textit{follow-up} \textarabic{بعد التحاليل}''. In a topic classification setting, the primary classifier may initially predict the label \textit{medical} with an associated confidence score. If this confidence score is high, the prediction is accepted directly. If the score is below the routing threshold, the sentence is escalated to the topic-specialist agents. In this escalated path, the Lexical Agent may focus on explicit cues such as \textit{patient} and \textit{follow-up}, the Logical Agent may reason that the situation describes clinical care, and the Contextual Agent may interpret the sentence as a healthcare-related interaction. The consensus mechanism then combines these perspectives with the preserved primary prediction before the final topic label is produced.

The following subsections describe the main stages of the pipeline in detail, beginning with the primary classification layer, followed by confidence-aware routing, task-specific specialist agents, consensus-based decision making, and explanation generation.





\subsection{Primary Classification Layer}
\label{sec:primary-classification-layer}

The primary classification layer is the entry point of the multi-agent pipeline. When an input sentence is received, the pipeline first attempts to classify it using a task-specific supervised model before invoking any agent-based reasoning. This stage produces an initial predicted label together with a confidence score that reflects how certain the model is about its decision.

The purpose of this layer is to handle straightforward cases efficiently. Many sentences can be classified with high confidence by the primary model alone, and sending all inputs to the agentic reasoning stage would unnecessarily increase computational cost. Therefore, the primary classifier acts as a fast first-pass predictor. Its output determines whether the sentence can be accepted immediately or whether additional reasoning is required.

The primary classifier is treated as a model-agnostic component. The pipeline does not depend on a specific backbone architecture; it only requires that the classifier produce a predicted label and a confidence estimate over the task label space. This allows the same multi-agent design to be used with different classifiers and across different tasks.

In this thesis, the pipeline is applied to topic classification and sentiment classification. For each task, the primary classifier operates over the corresponding label space and provides the initial prediction used by the routing mechanism. The details of the specific classifier architectures and training configurations are presented in the experimental setup chapter.

By separating the primary classifier from the specialist agents, the pipeline preserves the efficiency of direct classification for confident cases while reserving agent-based reasoning for uncertain instances. The next subsection describes how the confidence-aware router decides which path a sentence should follow.




\subsection{Confidence-Aware Routing}
\label{sec:confidence-aware-routing}

After the primary classifier produces an initial prediction, the pipeline decides whether this prediction is reliable enough to be accepted directly or whether the sentence requires additional agent-based reasoning. This decision is made by the confidence-aware router, which acts as the control point between the direct primary classification path and the specialist-agent path.

For an input sentence $x$, the primary classifier outputs a predicted label and a confidence score $c(x)$. The router compares this score with a predefined threshold $\tau$. If the confidence score is greater than or equal to the threshold, the prediction is returned without invoking the specialist agents. If the confidence score falls below the threshold, the sentence is escalated to the corresponding task-specific agent pipeline. In the escalated path, the primary prediction is not discarded; it is preserved and later used together with the specialist-agent outputs during consensus.

The routing decision is defined as

\begin{equation}
\mathrm{Route}(x)=
\left\{
\begin{array}{ll}
\mbox{Accept primary prediction}, & c(x) \geq \tau,\\
\mbox{Escalate to specialist agents}, & c(x) < \tau.
\end{array}
\right.
\end{equation}

where $c(x)$ denotes the confidence score assigned by the primary classifier to input sentence $x$, and $\tau$ denotes the confidence threshold.

The threshold $\tau$ is treated as a configurable parameter rather than a fixed universal value. This is important because different tasks and primary classifiers may produce different confidence distributions. A threshold that is suitable for one model may cause excessive escalation for another, or may accept uncertain predictions too early. Therefore, the threshold is selected according to the task and primary classifier used in each experiment, while the routing logic itself remains unchanged.

This routing mechanism allows the pipeline to reserve specialist-agent reasoning for uncertain cases, while keeping confident cases efficient. The next subsections describe the task-specific agent pipelines that are activated when escalation is required.




\subsection{Topic Classification Pipeline}
\label{sec:topic-classification-pipeline}

The topic classification pipeline is activated when the confidence-aware router determines that the primary topic classifier is not sufficiently confident. As shown in Figure~\ref{fig:topic-pipeline}, the input sentence first passes through the primary classification layer, which produces an initial topic prediction and confidence score. If the confidence score satisfies the threshold, the primary prediction is accepted directly. If the confidence score falls below the threshold, the sentence is escalated to the topic-specific specialist agents.

In the escalation path, the sentence is analyzed by three topic-specialized agents: the \textit{Lexical Agent}, the \textit{Logical Agent}, and the \textit{Contextual Agent}. Each agent receives the same input sentence but focuses on a different source of evidence. The Lexical Agent identifies explicit topic-indicative words and phrases, the Logical Agent reasons about which topic best matches the meaning of the sentence, and the Contextual Agent considers broader semantic cues that may indicate the topic even when it is not stated directly.

The outputs of these agents are then passed to the topic consensus mechanism. The consensus mechanism aggregates the specialist predictions together with the preserved primary prediction and confidence score in order to produce a final topic label. Therefore, the final topic decision in the escalated path is based on both the original classifier output and the complementary reasoning provided by the specialist agents.

Figure~\ref{fig:topic-pipeline} illustrates this process. The upper path represents high-confidence cases that are returned directly from the primary classifier, while the lower path represents low-confidence cases that are routed to the specialist agents before the final topic prediction is produced. The following subsections describe the responsibilities of each topic specialist agent and the consensus mechanism in more detail.

\subsubsection{Lexical Agent}
\label{subsec:topic-lexical-agent}

The \textit{Lexical Agent} represents the surface-evidence component of the topic classification pipeline. Its role is to inspect the input sentence for explicit words, phrases, and named entities that directly signal a topic category. In many code-switched sentences, the topic can be partially inferred from visible lexical markers, such as English technical terms, Arabic domain-specific expressions, product names, medical terms, or financial vocabulary. The Lexical Agent therefore focuses on these observable cues before any deeper contextual or logical interpretation is applied.

The agent is guided by a role-specific instruction prompt that directs it to focus on observable lexical cues rather than broader contextual interpretation. This constraint gives the Lexical Agent a narrow but useful responsibility: it identifies the surface-level indicators that are directly visible in the sentence. For example, words related to payments, prices, or banking may support a finance label, while terms related to doctors, medication, or diagnosis may support a medical label.

For each escalated sentence, the Lexical Agent produces a structured output containing a predicted topic label, a confidence score, and a short explanation of the lexical cues that motivated its prediction. This output is then passed to the Topic Consensus module, where it is combined with the predictions of the Logical and Contextual Agents, together with the preserved primary classifier prediction and confidence score.

The Lexical Agent is especially useful when the sentence contains clear topic-indicative vocabulary. However, not all topics are expressed through direct keywords. Some sentences require reasoning about the situation described or interpreting the broader meaning of the text. For this reason, the lexical analysis is followed by the Logical Agent, which examines the sentence from a more structured reasoning perspective.

\subsubsection{Logical Agent}
\label{subsec:topic-logical-agent}

The \textit{Logical Agent} provides the second specialist perspective in the topic classification pipeline. While the Lexical Agent focuses on visible topic cues, the Logical Agent examines how the ideas in the sentence relate to one another. Its role is to infer the most appropriate topic by reasoning over the entities, actions, and events described in the input, especially when the topic is not expressed through direct keywords.

The agent is guided by a role-specific instruction prompt that encourages systematic reasoning over the semantic content of the sentence. Instead of selecting a label only because certain words appear in the text, the Logical Agent evaluates what is happening in the sentence and which topic category is most logically supported by that meaning. This allows the pipeline to handle cases where the topic is implied through the described situation rather than explicitly stated.

For each escalated sentence, the Logical Agent produces a structured output containing a predicted topic label, a confidence score, and a short explanation of the reasoning behind its prediction. This output is then passed to the Topic Consensus module, where it is combined with the predictions of the Lexical and Contextual Agents, together with the preserved primary classifier prediction and confidence score.

The Logical Agent is particularly useful when lexical evidence alone is insufficient. However, some sentences also require broader interpretation beyond the immediate logical relations in the text, such as understanding the overall communicative context or the implied topic of a sentence. This motivates the use of the Contextual Agent, which provides the third specialist perspective in the topic classification pipeline.

\subsubsection{Contextual Agent}
\label{subsec:topic-contextual-agent}

The \textit{Contextual Agent} provides the third specialist perspective in the topic classification pipeline. While the Lexical Agent focuses on visible topic cues and the Logical Agent reasons over the relationships between concepts, the Contextual Agent interprets the sentence as a whole. Its role is to capture the broader meaning of the input, especially in cases where the intended topic is implied, ambiguous, or dependent on how different parts of the sentence work together.

The agent is guided by a role-specific instruction prompt that encourages an integrated interpretation of the input. Rather than selecting a label based only on isolated words or individual semantic relations, the Contextual Agent considers how the words, entities, actions, and events collectively shape the meaning of the sentence. This allows it to identify topics that may not be directly signaled through explicit vocabulary but are still clear from the overall context.

For each escalated sentence, the Contextual Agent produces a structured output containing a predicted topic label, a confidence score, and a short explanation of the contextual evidence supporting its prediction. This output is then passed to the Topic Consensus module, where it is combined with the predictions of the Lexical and Logical Agents, together with the preserved primary classifier prediction and confidence score.

By adding this broader contextual perspective, the Contextual Agent completes the topic-specialist panel. The three agents therefore provide complementary forms of evidence: lexical cues, logical interpretation, and contextual meaning. These outputs are then aggregated by the Topic Consensus module to produce the final topic prediction for escalated instances.


\subsubsection{Topic Consensus}
\label{subsec:topic-consensus}

After the Lexical, Logical, and Contextual Agents produce their topic predictions, their outputs are passed to the \textit{Topic Consensus} module. This module is responsible for converting the different predictions into a single final topic label for the escalated instance. The consensus stage does not discard the primary classifier output; instead, it keeps the primary prediction and confidence score as part of the decision process.

The module receives a predicted topic label and confidence score from each participating component: the primary classifier, the Lexical Agent, the Logical Agent, and the Contextual Agent. Each component therefore contributes evidence toward one of the possible topic labels. When several components support the same label with high confidence, that label receives stronger overall support. In contrast, predictions made with lower confidence have less influence on the final decision.

The aggregation process follows a confidence-aware voting strategy. Let $\mathcal{C}$ denote the set of topic labels, and let $\mathcal{A}$ denote the set of participating components. Each component $a_i \in \mathcal{A}$ produces a predicted label $y_i \in \mathcal{C}$ and an associated confidence score $c_i$. The final topic prediction is computed as

\begin{equation}
\hat{y} =
\arg\max_{y \in \mathcal{C}}
\sum_{a_i \in \mathcal{A}}
\mathbb{I}(y_i = y) \cdot c_i ,
\end{equation}

where $\mathbb{I}(y_i = y)$ is an indicator function that equals 1 when component $a_i$ predicts label $y$ and 0 otherwise. This formulation allows the final prediction to reflect both agreement among components and the confidence assigned to each prediction.

The confidence values produced by the specialist agents are treated as relative indicators of certainty rather than fully calibrated probabilities. Their role is therefore to weight the voting process, not to provide an absolute probability of correctness. This is important because the primary classifier and the LLM-based agents may produce confidence estimates with different calibration properties.

Once the final topic label is selected, the consensus output is passed to the Explainability Agent. The Explainability Agent uses the final prediction and the supporting evidence from the primary classifier and specialist agents to generate a natural-language explanation of the decision.


\subsection{Sentiment Classification Pipeline}
\label{sec:sentiment-classification-pipeline}

The sentiment classification pipeline extends the same confidence-aware multi-agent design used for topic classification, but adapts the specialist roles to sentiment analysis. Its goal is to assign each input sentence one of three sentiment labels: \textit{positive}, \textit{negative}, or \textit{neutral}. Since sentiment classification depends not only on what is mentioned in the sentence but also on whether an evaluative stance is actually expressed, this pipeline requires specialists that can capture sentiment-bearing language, polarity, and contextual meaning.

For this reason, the sentiment pipeline replaces the Logical Agent used in topic classification with a \textit{Polarity Agent}. While the topic pipeline uses logical reasoning to infer the most appropriate subject category, the sentiment pipeline needs to determine whether the sentence expresses an opinion and, if so, whether that opinion is positive or negative. The escalated sentiment path therefore consists of three specialist agents: the \textit{Lexical Agent}, the \textit{Polarity Agent}, and the \textit{Contextual Agent}.

Each sentiment specialist examines the same input sentence from a different perspective. The Lexical Agent identifies explicit sentiment-bearing words and expressions. The Polarity Agent analyzes the evaluative orientation of the sentence and determines its sentiment direction. The Contextual Agent considers broader communicative meaning, including implicit sentiment, ambiguity, figurative language, and code-switching patterns that may affect interpretation.

The outputs of these agents are passed to the Sentiment Consensus module, where they are combined with the preserved primary classifier prediction and confidence score. The resulting preliminary decision is then checked by the \textit{Selective IntentGate}, which verifies whether the sentence actually expresses an evaluative opinion before the final sentiment label is returned. This step helps prevent unsupported positive or negative predictions when the sentence is more appropriately interpreted as neutral.

Figure~\ref{fig:sentiment-pipeline} summarizes the execution flow of the sentiment pipeline. High-confidence inputs follow the direct path and return the primary prediction, while low-confidence inputs follow the escalation path through the sentiment specialist agents, consensus module, and Selective IntentGate.

For example, consider the sentence: ``\textarabic{الفيلم كان} \textit{boring} \textarabic{جدًا ومضيعة وقت}''. In this case, the Sentiment Lexical Agent may identify explicit negative cues such as \textit{boring} and ``\textarabic{مضيعة وقت}''. The Polarity Agent may then determine that these cues express the author's negative evaluation rather than merely mentioning sentiment-related language. The Contextual Agent may confirm that the sentence as a whole communicates dissatisfaction with the film. These outputs are combined by the Sentiment Consensus module, and the Selective IntentGate verifies that the sentence contains an expressed evaluative stance before the final negative label is returned.

The following subsections describe the three sentiment specialist agents, the Sentiment Consensus module, and the Selective IntentGate in more detail.





\subsubsection{Lexical Agent}
\label{subsec:sentiment-lexical-agent}

The \textit{Sentiment Lexical Agent} provides the first specialist view of an escalated sentiment instance. At this stage, the pipeline looks at the sentence through its most visible evidence: the words, expressions, symbols, and surface markers that may signal sentiment. This is important in Arabic-English code-switched text because sentiment is often expressed through a mixture of Arabic expressions, English affective words, emojis, punctuation, or informal platform-specific language. Before the pipeline performs deeper reasoning, the Lexical Agent captures these explicit clues and evaluates how strongly they support a positive, negative, or neutral interpretation.

Unlike the lexical agent used for topic classification, this agent does not search for words that indicate a semantic domain. Instead, it focuses on language that may carry evaluative meaning. A word, phrase, or emoji may appear to suggest sentiment, but the agent is not expected to treat such cues as automatic decisions. For example, a term such as ``dislike'' may indicate a negative opinion when it is used to express the author's stance, but it may also appear in a neutral question about a platform interaction. The agent therefore examines whether the lexical cue is genuinely being used to express sentiment or whether it is only being mentioned, quoted, or used as an artifact of the text.

The agent is guided by a role-specific instruction prompt that keeps its analysis centered on lexical evidence. For each escalated sentence, it produces a structured output containing a predicted sentiment label, a confidence score, a short explanation, and the lexical cues that motivated its decision. When the visible evidence is clear and consistent, the agent can provide a confident prediction. When the evidence is weak, conflicting, or based mainly on isolated symbols such as emojis or repeated punctuation, the agent lowers its confidence rather than forcing a strong polarity decision.

In this way, the Sentiment Lexical Agent gives the pipeline an explicit evidence-based starting point for sentiment reasoning. Its output captures what can be inferred from the surface form of the sentence, while leaving deeper questions of evaluative stance and contextual meaning to the remaining specialists. The next stage therefore moves from visible sentiment cues to the Polarity Agent, which examines whether the author is actually expressing an evaluative orientation and what polarity that orientation supports.


\subsubsection{Polarity Agent}
\label{subsec:sentiment-polarity-agent}

After the Sentiment Lexical Agent identifies the visible sentiment cues in the sentence, the pipeline moves to a deeper question: whether these cues actually express the author's evaluative stance. This is the role of the \textit{Polarity Agent}. Rather than focusing only on the presence of positive or negative words, the Polarity Agent examines whether the sentence conveys an opinion and, if so, whether that opinion is positive, negative, or neutral.

This distinction is important because sentiment-related language does not always correspond to expressed sentiment. A sentence may mention a negative word, quote another person's opinion, describe a situation, or refer to a platform action without expressing the author's own evaluation. The Polarity Agent is therefore designed to separate genuine evaluative stance from sentiment vocabulary that is only referenced or described. In this way, it provides a more targeted form of reasoning than the Lexical Agent, which mainly captures surface-level evidence.

The agent is guided by a role-specific instruction prompt that encourages it to reason through the sentiment decision in stages. It first considers whether an evaluative opinion is present. If the sentence does express an evaluation, the agent then determines the direction of that evaluation as \textit{positive}, \textit{negative}, or \textit{neutral}. During this process, it considers semantic signals such as negation, intensifiers, conflicting sentiment cues, and implicit evaluations. When the evidence is weak or ambiguous, the agent lowers its confidence instead of forcing a strong polarity decision.

For each escalated sentence, the Polarity Agent produces a structured output containing a predicted sentiment label, a confidence score, a short explanation, and the evidence used to justify the selected polarity. This output is then passed to the Sentiment Consensus module, where it is combined with the predictions of the Lexical and Contextual Agents, together with the preserved primary classifier prediction and confidence score.

By adding this reasoning step, the sentiment pipeline can move beyond visible sentiment words and examine the stance expressed by the sentence as a whole. However, some cases still require broader interpretation, especially when the sentiment is implicit, ironic, context-dependent, or affected by code-switching. These cases motivate the next specialist, the Contextual Agent, which analyzes the wider communicative meaning of the input.


\subsubsection{Contextual Agent}
\label{subsec:sentiment-contextual-agent}

After the Lexical Agent captures visible sentiment cues and the Polarity Agent examines the expressed evaluative stance, the \textit{Contextual Agent} provides the final specialist view of the escalated sentence. Its role is to interpret the message as a whole and determine how the different parts of the sentence work together to express sentiment. This is especially important for Arabic-English code-switched text, where sentiment may depend on informal expressions, mixed-language phrasing, implicit meaning, or the communicative situation rather than on isolated words.

The Contextual Agent is designed for cases where sentiment cannot be understood reliably from lexical cues or polarity reasoning alone. A sentence may contain emotional language without expressing the author's own opinion, or it may express criticism, praise, sarcasm, or mockery indirectly. It may also describe content, quote another person, comment on platform interaction, or use humor in a way that changes the apparent sentiment. The Contextual Agent therefore considers the full communicative function of the message before assigning a sentiment label.

The agent is guided by a role-specific instruction prompt that encourages whole-message interpretation. Instead of treating each word or phrase independently, it evaluates how words, entities, actions, and discourse cues interact within the sentence. When surface-level sentiment cues conflict with the broader meaning, the Contextual Agent prioritizes the overall interpretation of the message. If the author's stance remains genuinely unclear after contextual analysis, the agent lowers its confidence or favors a neutral interpretation.

For each escalated sentence, the Contextual Agent produces a structured output containing a predicted sentiment label, a confidence score, a short explanation, and the contextual evidence supporting its decision. This output is then passed to the Sentiment Consensus module, where it is combined with the predictions of the Lexical and Polarity Agents, together with the preserved primary classifier prediction and confidence score.

By adding this holistic perspective, the Contextual Agent completes the sentiment-specialist panel. The three agents therefore move from visible sentiment cues, to evaluative polarity, to full contextual interpretation. Their outputs are then aggregated by the Sentiment Consensus module before the Selective IntentGate performs the final verification step.

\subsubsection{Sentiment Consensus}
\label{subsec:sentiment-consensus}

After the Lexical, Polarity, and Contextual Agents complete their analysis, their predictions are passed to the \textit{Sentiment Consensus} module. This module combines the different sentiment judgments into a single preliminary prediction. Unlike the final output stage, this prediction is not returned immediately; it is first forwarded to the Selective IntentGate for an additional verification step.

The consensus mechanism follows the same confidence-aware voting principle used in the topic classification pipeline, but it operates over the sentiment-specific components. The participating components are the primary classifier, the Sentiment Lexical Agent, the Polarity Agent, and the Contextual Agent. Each component contributes its predicted sentiment label and confidence score, allowing the module to consider both agreement among components and the strength of each prediction.

The aggregation process assigns support to each sentiment label according to the confidence of the components that selected it. A label supported by several confident components receives stronger accumulated evidence, while an isolated or low-confidence prediction has less influence on the result. In this way, the consensus module reconciles the different specialist perspectives while still preserving the primary classifier as part of the decision process.

Formally, let $\mathcal{C}$ denote the set of sentiment labels, and let $\mathcal{A}$ denote the set of participating components. Each component $a_i \in \mathcal{A}$ predicts a label $y_i \in \mathcal{C}$ with confidence score $c_i$. The preliminary consensus prediction is computed as

\begin{equation}
\hat{y}=
\arg\max_{y\in\mathcal{C}}
\sum_{a_i\in\mathcal{A}}
\mathbb{I}(y_i=y)\cdot c_i ,
\end{equation}

where $\mathbb{I}(y_i=y)$ is an indicator function that equals 1 when component $a_i$ predicts label $y$ and 0 otherwise.

The output of this stage represents the collective decision of the voting components. However, because sentiment classification is sensitive to whether the author is actually expressing an evaluative opinion, the consensus decision is treated as an intermediate prediction. It is therefore passed to the Selective IntentGate, which checks whether the predicted polarity is supported by an expressed stance before the final sentiment label is produced.
\subsubsection{Selective IntentGate}
\label{subsec:selective-intentgate}

After the Sentiment Consensus module produces a preliminary sentiment prediction, the pipeline applies a final verification step through the \textit{Selective IntentGate}. This stage is introduced because sentiment classification does not only require identifying positive or negative cues; it also requires determining whether the author is actually expressing an evaluative stance. In some cases, a sentence may contain sentiment-related language but still be neutral, such as when it refers to a platform interaction, quotes another opinion, describes media content, or mentions sentiment without expressing it.

Unlike the Lexical, Polarity, and Contextual Agents, the Selective IntentGate is not a voting specialist. It does not add another sentiment prediction to the consensus process and does not contribute any voting weight. Instead, it operates after consensus as a verification module. Its role is to check whether a preliminary polar prediction is supported by an expressed authorial evaluation or whether the sentence is more appropriately treated as neutral.

The gate is guided by a role-specific instruction prompt that focuses on distinguishing genuine evaluative intent from non-evaluative content. It considers cases such as platform interactions, quotations, media references, plot or content descriptions, and other meta-level expressions where sentiment-related words may appear without reflecting the author's own stance. If the sentence expresses an evaluative opinion, the gate preserves the consensus prediction. If no evaluative stance is detected, the gate prevents unsupported neutral-to-polar overrides.

This verification strategy is intentionally conservative. The Selective IntentGate does not introduce a new positive or negative label, and it does not freely replace the consensus decision. It only intervenes in a specific case: when the primary classifier predicts \textit{neutral}, the consensus module changes this prediction to a polar label, and the gate determines that no authorial evaluation is expressed. In this case, the gate rejects the polar override and restores the neutral prediction. Otherwise, the consensus prediction is accepted.

Algorithm~\ref{alg:intentgate-pipeline} summarizes the Selective IntentGate verification process.

\begin{algorithm}[H]
\caption{Selective IntentGate Verification}
\label{alg:intentgate-pipeline}
\begin{algorithmic}[1]
\REQUIRE Consensus prediction $y_c$, primary prediction $y_p$, IntentGate output $y_g$
\IF{$y_p = \textit{neutral}$ \textbf{and} $y_c \neq \textit{neutral}$}
    \IF{$y_g = \textit{neutral}$}
        \STATE Reject consensus override
        \STATE Final prediction $\gets y_p$
    \ELSE
        \STATE Final prediction $\gets y_c$
    \ENDIF
\ELSE
    \STATE Final prediction $\gets y_c$
\ENDIF
\end{algorithmic}
\end{algorithm}

The selectivity of the gate comes from the instruction prompt rather than from a different aggregation rule. The algorithm defines when the gate is allowed to intervene, while the prompt defines how the gate distinguishes expressed sentiment from non-evaluative content. This design allows the pipeline to keep the benefits of specialist sentiment reasoning while reducing false polar predictions in cases where the input does not express a genuine evaluative stance.


\subsection{Explainability Agent}
\label{sec:explainability-agent}

The \textit{Explainability Agent} is the final component of the multi-agent pipeline. After the prediction has already been produced, this agent generates a natural-language explanation that helps the user understand why the system selected the final label. Unlike the specialist agents, it does not participate in classification, voting, consensus, or verification. Its role is explanatory rather than predictive.

The agent receives the final predicted label together with the intermediate information generated during inference. This includes the primary classifier prediction and confidence score, the outputs of the specialist agents, the consensus decision, and, in the sentiment pipeline, the result of the Selective IntentGate when it is applied. Using these inputs, the Explainability Agent summarizes the evidence that contributed most strongly to the final decision.

The agent is guided by a role-specific instruction prompt that focuses on explanation synthesis. The prompt instructs it to produce a concise and coherent justification that remains consistent with the final pipeline output. It is not allowed to introduce a new prediction, override the selected label, or provide an alternative interpretation. Instead, it organizes the reasoning already produced by the pipeline into a clear, human-readable explanation.

Because the Explainability Agent is task-independent, the same mechanism is used for both topic and sentiment classification. In topic classification, the explanation summarizes the lexical, logical, and contextual evidence supporting the selected topic. In sentiment classification, it summarizes the lexical, polarity, and contextual evidence, and may also mention whether the Selective IntentGate confirmed or blocked a polar interpretation.

By separating explanation from prediction, the pipeline improves interpretability without changing the classification result. The final output therefore includes both the predicted label and a justification that shows how the different components contributed to the decision.


\subsection{Pipeline Summary}
\label{sec:multi-agent-pipeline-summary}

The proposed multi-agent pipeline combines a task-specific primary classifier with confidence-aware routing and specialist agent reasoning. Confident predictions are accepted directly, while uncertain instances are escalated to task-specific specialist agents for additional analysis.

For topic classification, the escalated path uses Lexical, Logical, and Contextual Agents. For sentiment classification, the Logical Agent is replaced by a Polarity Agent, and the preliminary consensus decision is further verified by the Selective IntentGate. In both tasks, the specialist outputs are integrated with the preserved primary prediction through a confidence-aware consensus mechanism.

Finally, the Explainability Agent converts the final decision and supporting intermediate outputs into a natural-language explanation. This structure allows the pipeline to combine efficient primary classification, selective agent-based reasoning, and interpretable prediction within a unified downstream evaluation framework.
